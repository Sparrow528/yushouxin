# 交接：数据与业务逻辑（UI 层）

> 适用：`products/` 产品目录
> 一句话：**改数据去 `catalog-data.js` 和 Supabase；`products/index.html` 只负责渲染，不要动它的结构和选择器。**

---

## 1. 文件职责

| 层 | 文件 | 谁改 |
|---|---|---|
| UI 结构 / 样式 / 交互 | `products/index.html` | UI 维护者 |
| 会员名单、品类分组、四语界面词条 | `products/catalog-data.js` | 逻辑 / 数据维护者 |
| 单个产品的英/法/阿译名与描述 | `products/i18n-products.js` | 逻辑 / 数据维护者 |
| 产品数据（线上真源） | Supabase `products` 表 | 数据维护者 |
| 首屏缓存 | `data/products.json` | **只由脚本生成，不要手改** |
| 缓存生成脚本 | `tools/sync-cache.ps1` | 逻辑维护者 |

## 3. 数据契约

`products` 表 / `data/products.json` 里每条产品：

| 字段 | 说明 |
|---|---|
| `id` | bigint 自增，**插入时不要手填** |
| `name` | 产品名（中文原文） |
| `price` | 文本；无定价填 `询价` |
| `category` | 品类短键，应与 `catalog-data.js` 的 `CAT_I18N` 对应 |
| `description` | 产品介绍 |
| `image` | 形如 `images/<会员简码>/<文件>.jpg`，**相对 `products/` 目录**，不是仓库根 |
| `specs` | 三选一：空字符串 / `键:值|键:值` / JSON 字符串 |
| `member_id` | 会员简码，应与 `MEMBERS` 中的 `id` 对应 |
| `created_at` | 自动生成 |

前端对不完整数据有兜底，不会报错：
- 品类没登记 → 自动归入「其他」分组
- 会员没登记 → 显示 `member_id` 本身（不会串到别家名下）
- 没有图片 → 显示品类占位块
- `specs` 解析不出 → 详情页显示原文

## 4. 加载顺序

```
data/products.json  →  Supabase REST  →  localStorage 缓存  →  内置兜底数据
```

所以「改了数据页面没变」通常不是代码问题，而是**没有重新生成缓存**。跑：

```powershell
$env:SUPABASE_SERVICE_KEY = '<service role key>'
.\tools\sync-cache.ps1
```

---

## 5. 常见改动怎么做

**加一个产品**：图片放 `products/images/<会员>/` → Supabase 插一行（不带 `id`）→ 跑 `sync-cache.ps1` → 提交 `data/products.json`。

**加一个新品类**：`catalog-data.js` 里 ①四语字典各加一行 `pc_<短键>` ②`CAT_I18N` 加映射。想在分类条归到某个一级组，再改 `CATEGORY_GROUPS`（**可跳过**，不登记会自动进「其他」）。

**加一家会员**：`catalog-data.js` 的 `MEMBERS` 加一条，`id / name / nameEn / nameFr / nameAr / category 四语 / intro 四语` 填齐。

**补外语产品名**：`i18n-products.js` 里按 `id` 加 `en / fr / ar` 的 `name` 与 `desc`。

**改询价收件邮箱**：这是 `index.html` 里唯一该改的业务常量，搜索 `INQUIRE_EMAIL`。改它安全。

## 6. 明确不要做

- 不要改 `#rows` / `#catBar` / `#panelBody` 的 DOM 结构（事件委托依赖节点稳定）
- 不要移除任何 `data-id` / `data-group` / `data-cat` / `data-inq` 属性
- 不要手改 `data/products.json`（会被脚本覆盖，且 count 容易与数组不一致）
- 不要在 `index.html` 里新增数据源或业务规则；需要新字段就先在 UI 里留好渲染位
- 不要引入框架、构建步骤、外部字体 CDN（当前是纯 HTML + 原生 JS，零依赖）
- 不要把 Supabase service role key 写进任何前端文件或提交到仓库

## 8. 交接时仍存在的问题（供逻辑层处理）

1. 木林森（39 个）与世农种苗（48 个）的产品名仍是「M系列 1」「番茄 3」这类占位，介绍是「产品介绍待补充」，其余 128 个产品有真实名称与参数。
2. 询价走 `mailto:`，不落库，无法统计线索。要落库需新增表并替换 `sendInquiry()` 里的一行。
3. 详情页图片多为产品册 PDF 页面裁切，需要更高清的产品主视觉素材。
4. `assets/logo.png`、`assets/logo-round.png` 是宇守信（红色印章）的素材，已无页面引用，属残留文件，可删除。
